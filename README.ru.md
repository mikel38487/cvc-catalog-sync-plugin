Один плагин для трёх вещей, которые нужны профилю DSH с маршрутом
CheapVibeCode:

1. **Синхронизация каталога** держит `llm-pi-ai.providers.<провайдер>.models` и
   список моделей сабагентов в соответствии с `GET /v1/models` и с уровнями
   мышления из официального установщика CheapVibeCode.
2. **Коэффициенты** ставят рядом с каждой моделью этого провайдера в выборе
   модели множитель цены (`×0.1` … `×10`).
3. **Баланс** добавляет кнопку в сайдбар и панель с остатком и расходом с
   прошлого замера.

У каждой из трёх функций свой переключатель на странице настроек. Выключенная
функция не оставляет после себя ничего: ни маршрута, ни таймера, ни инструмента,
ни элемента интерфейса. Версия 2.0.0 заменяет два прежних плагина
(`cvc-model-coeff-plugin` и `cvc-balance-plugin`) и переносит их возможности в
этот пакет, поэтому в профильном патче достаточно одной строки.

## Требования

- DeepSeek Harness `>=0.2.2-rc.3 <0.4.0`;
- Node.js 20 или новее;
- маршрут провайдера в `llm-pi-ai`, чей `baseURL` указывает на хост
  `cheapvibecode.ru` (по умолчанию `https://ru.cheapvibecode.ru/v1`), с ключом,
  имя которого задано в `apiKeyEnv` (по умолчанию `CVC_DEEPSEEK_API_KEY`).

Если такого маршрута нет, каталогу и балансу не у кого читать: план и
применение сообщают, что маршрут не найден, и панель баланса говорит то же
самое. Сама страница настроек при этом работает — она ведь и есть переключатель
функций.

## Установка

Попросите агента DSH поставить бандл из npm:

```text
install the npm bundle cvc-catalog-sync-plugin
```

Вручную: добавьте `"cvc-catalog-sync-plugin": "^2.0.0"` в зависимости
`~/.dsh/profiles/<профиль>/package.json`, допишите имя пакета в
`dsh.profile.bundles` и дайте профилю установить его. Бандл содержит собранный
`client.js`, поэтому при установке ничего не собирается и разрешение
`allowBuilds` не требуется. Для локального чекаута используйте
`"cvc-catalog-sync-plugin": "link:<абсолютный путь>"`.

Имя пакета — `cvc-catalog-sync-plugin`, id строки композиции —
`cvc-catalog-sync`: профиль не нужно переписывать ради обновления. Шаги, которые
действительно меняются, — в [docs/UPGRADING.md](docs/UPGRADING.md).

## Где настройки

Одна и та же форма открывается в двух местах:

- **Настройки → CVC** — раздел навигации настроек со своим значком
  (`settings.section` + `settings.section.icon`, id `cvc`, order 25);
- **Плагины → CVC catalog sync → страница бандла** — блок конфигурации между
  описанием бандла и списком компонентов (`plugins.bundle.config` с ключом по
  имени пакета). В свёрнутом списке блок показывается одной строкой-сводкой.

Сверху одна группа переключателей (**Функции**), затем группы параметров:
**Каталог**, **Коэффициенты**, **Баланс** и **Дополнительно**. Переключатели
решают, действует ли соответствующая группа; **Дополнительно** содержит поиск
провайдеров (`providers.*`) и кэш уровней и виден при всех выключенных функциях,
потому что настраивает общий для всех трёх поиск.

| Переключатель | Что включает |
|---|---|
| Синхронизация каталога | прогоны при старте и по таймеру, инструмент `cvc_catalog`, `POST /cvc/run` и то, что умеют кнопки проверки и применения |
| Коэффициенты | `GET /cvc/coefficients` и бейджи в выборе модели |
| Баланс | `GET /cvc/balance`, инструмент `cvc_balance`, кнопка в сайдбаре и панель |

Страница настроек и `GET /cvc/state` не гейтятся: они существуют и при всех трёх
выключенных функциях, потому что страница и есть переключатель. Кнопки проверки и
применения остаются на странице и при выключенной синхронизации, но маршрут
прогона за ними отвечает `404`, и страница сообщает о неудачном прогоне.

Изменение применяется через `PUT /cvc/config` и действует сразу: все поля
конфигурации объявлены volatile, поэтому DSH перезагружает строку без
перезапуска плагина. Выключение функции снимает её с монтирования, включение
возвращает — в той же сессии страницы.

Переключатели называются **Синхронизация каталога**, **Коэффициенты моделей** и
**Баланс**, и страница настроек прямо говорит, что остаётся после выключения:
маршрут функции отвечает `404`, таймер не создаётся, элемент интерфейса
исчезает. Сама страница остаётся всегда — это и есть переключатель.

Кнопки:

| Кнопка | Что делает |
|---|---|
| **Сохранить** | Проверяет форму и пишет строку конфига в профильный патч через `configEditor.edit()`. Значение, равное умолчаниям схемы, убирает переопределение, поэтому в патче остаются только реальные изменения. |
| **Проверить каталог** | Забирает каталог и карту уровней, показывает разницу, ничего не записывает. |
| **Применить каталог** | Тот же запрос, затем запись моделей и списка сабагентов. Сначала спрашивает подтверждение. |
| **Сбросить** | Подставляет умолчания в форму; нажмите «Сохранить», чтобы убрать переопределение. |

Проверка и применение используют **сохранённые** настройки, поэтому сначала
«Сохранить»; несохранённые изменения страница помечает. Под кнопками — итог
последнего прогона: число моделей в каталоге, сейчас и будет, источник уровней,
добавленные, удалённые и изменённые модели, правки списка сабагентов,
предупреждения и путь патча.

## Конфигурация

Переопределяйте строку в профильном патче по id `cvc-catalog-sync` — или
пользуйтесь страницей настроек, она пишет ту же строку. Перечислять нужно только
те поля, которые хотите изменить:

```yaml
- id: cvc-catalog-sync
  name: 'cvc-catalog-sync-plugin'
  config:
    features:
      catalogSync: true
      coefficients: true
      balance: true
    providers:
      match: ['cheapvibecode.ru']       # хосты, по которым узнаётся провайдер
      entryId: llm-pi-ai                # строка патча с маршрутами провайдеров
      apiKeyEnv: CVC_DEEPSEEK_API_KEY   # запасное имя ключа, не значение
      baseURL: https://ru.cheapvibecode.ru/v1
      timeoutMs: 20000
    catalog:
      provider: cheapvibecode           # ключ маршрута, чьи models пишутся
      autoSync: true                    # прогон при старте и по интервалу
      intervalHours: 24                 # 0 выключает таймер; меньше минуты — поднимается
      startupDelayMs: 5000
      minModelRatio: 0.8                # не принимать каталог меньше этой доли
      keepModels: []                    # id, которые сохраняются, даже если каталог их убрал
      installerUrls:                    # карты уровней, уровни берутся из первого доступного
        - https://ru.cheapvibecode.ru/idhw
        - https://ru.cheapvibecode.ru/idhl
      syncAllowlist: true
      allowlistEntryId: subagent-model-selection-settings
      levelsCacheMinutes: 360
    coefficients:
      refreshMinutes: 10
      showFast: true
    balance:
      refreshSeconds: 0                 # 0 — только по кнопке; минимум 15
      showDelta: true
```

Умолчания те же, что в таблице [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md);
записанное в патч значение переопределяет умолчание, удалённое поле возвращает
его обратно.

Конфигурация версии 1.x по-прежнему загружается: плоские ключи (`entryId`,
`provider`, `baseURL`, `apiKeyEnv`, `installerUrls`, `autoSync`,
`intervalHours`, `startupDelayMs`, `minModelRatio`, `keepModels`,
`syncAllowlist`, `allowlistEntryId`, `levelsCacheMinutes`, `timeoutMs`)
принимаются как устаревшие поля и раскладываются по группам. В этом случае
`GET /cvc/state` сообщает `configShape: legacy`, а страница настроек предлагает
один раз сохранить, чтобы перейти на новый вид.

## Каталог

Каталог CVC (`GET /v1/models`) меняется часто и **не содержит** уровней
мышления — только булев `supports_reasoning`. Уровни лежат литералом
`const reasoningLevels = {...}` внутри официальных установщиков (`/idhw` для
PowerShell, `/idhl` для bash). Штатное действие DSH «получить список моделей»
ничего не сохраняет и уровней не возвращает, поэтому обновление каталога иначе —
ручная правка `~/.dsh/profiles/<профиль>/cordis.patch.yml`.

Что делает прогон:

1. При активации, после `startupDelayMs`, и каждые `intervalHours` (если
   `autoSync` включён) забирает `{baseURL}/models` ключом маршрута и карту
   `reasoningLevels` установщика.
2. Собирает `llm-pi-ai.providers.<провайдер>.models` по правилам самого
   установщика: `name` — хвост `display_name` после ` · `, `contextWindow` —
   `context_window`, `maxTokens` — `min(max_output_tokens, contextWindow)`,
   `input` получает `image`, если модель его принимает, уровень `none`
   превращается в `off: none`, а `gpt-image*` и модели без текстового вывода
   пропускаются.
3. Пишет результат через `ctx.configEditor.edit()`: сохраняются остальные
   строки патча, комментарии и строки чужих плагинов, а изменение применяется
   через `dsh-hmr` без перезапуска DSH.
4. При включённом `syncAllowlist` список
   `subagent-model-selection-settings.allowedModels` приводится к тем же id
   моделей; записи других провайдеров не трогаются.

Запись выполняется только при реальном изменении каталога или списка. Ответ
меньше `minModelRatio` от текущего числа моделей отклоняется: частичный или
пустой каталог не должен стирать рабочий список.

### Инструмент cvc_catalog

| Действие | Что делает |
|---|---|
| `status` | Последний прогон в этом процессе; без сети |
| `plan` | Забрать, собрать, показать разницу, ничего не записывать |
| `apply` | Забрать и записать (отказ при усыхании каталога или при устаревшем каталоге, обходится `force: true`) |

Проверка и применение проходят одни и те же шаги. Прогон сообщает размер
каталога, текущее и будущее число моделей, источник уровней, добавленные,
удалённые и изменённые модели, правки списка сабагентов и предупреждения. Когда
API отвечает `409`, причина — отказ guard-а или устаревший каталог, а не сбой
сервера: страница показывает причину и предлагает `force` там, где инструмент его
принимает.

## Коэффициенты

Множитель приходит из того же ответа `GET /v1/models` и представляет собой
коэффициент к базовой цене провайдера, а не сумму в валюте. В меню выбора
модели и на кнопке текущей модели у композера справа от имени появляется бейдж
`×0.1`, `×3`, `×10`. Цвет берётся из темы хоста: зелёный до 0.5, обычный текст
до 1.5, предупреждение до 4, ошибка выше. Если fast-режим дороже обычного,
подсказка называет и его.

Бейдж получают только модели провайдера, чей `baseURL` указывает на
`cheapvibecode.ru`; та же модель с тем же id у другого провайдера остаётся без
украшения. Модель без коэффициента в каталоге остаётся без бейджа: плагин не
угадывает цену. Бейдж не кликабелен, а слот `conversation.input.model.label`
остаётся его владельцу, поэтому выбор модели не меняется — он по-прежнему у
штатного селектора.

Браузер спрашивает `GET /cvc/coefficients` каждые `refreshMinutes`. Ответ
отдаётся из общего кэша каталога, поэтому обновление бейджей не стоит лишнего
запроса к каталогу, пока кэш свеж. Параметр **Показывать быстрый режим** решает,
добавлять ли в подсказку множитель fast-режима; без него бейдж показывает только
обычный множитель.

## Баланс

В футере сайдбара появляется кнопка **CVC баланс** с маленькой точкой
состояния: зелёная, когда ответили все провайдеры, жёлтая — когда ответила
только часть (или идёт обновление), красная — когда не ответил никто, нейтральная —
когда провайдеров нет. Цвета — токены темы, поэтому точка читается и в светлой
теме.

Нажатие открывает панель с карточкой на каждый маршрут: отображаемое имя, ключ
маршрута, `baseURL`, имя ключа и найден ли он, остаток в единицах провайдера и
расход с прошлого замера (если `showDelta` включён). Панель можно перетаскивать,
она запоминает позицию в `localStorage` под ключом `cvc:panel-pos` и предлагает
кнопки **Обновить** и **Сбросить позицию**. За пределы окна панель не уходит и в
`document.body` не пишет.

`refreshSeconds` по умолчанию `0`: панель читает баланс при открытии или по
кнопке. Положительное значение от 15 включает таймер, который перечитывает
баланс, пока панель открыта; при закрытии панели таймер снимается. Значение от 1
до 14 поднимается до 15, а форма отклоняет его с ошибкой проверки, а не меняет
число молча.

Ошибка одного провайдера показывается на его карточке и не мешает остальным
ответить. Сам ключ с хоста не уходит: в ответе только `keySet: true|false` и
цифры.

### Инструмент cvc_balance

`status` возвращает последний снимок в этом процессе и не тратит запрос: по
каждому маршруту — флаг `keySet` и остаток в единицах. Он предназначен агенту,
человеку — панель, и существует инструмент только при включённой функции
баланса.

## HTTP-контракт

Все маршруты живут под одним префиксом `/cvc` и обслуживаются веб-сервером DSH
на том же origin, что и интерфейс.

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/cvc/state` | — | `{version, features, config, configShape, status, lastRun, patchPath, rowId}` |
| PUT | `/cvc/config` | `{config}` | `{ok, config, features}`; при ошибке `400` с `fields` |
| POST | `/cvc/run` | `{action: 'plan' \| 'apply', force?}` | результат прогона |
| GET | `/cvc/coefficients` | — | `{models, providers, fetchedAt, stale}`; `404`, если функция выключена |
| GET | `/cvc/balance` | — | `{providers, fetchedAt}`; `404`, если функция выключена |
| GET | `/cvc/health` | — | `{ok, version}` |

Межсайтовые запросы (`Sec-Fetch-Site: cross-site`) получают `403`, запись
(`PUT` или `POST`) без `application/json` — `415`, тело больше 64 КБ — `413`, а
неизвестный путь — `404`, а неверный метод на известном пути — `405`.

## Совместимость

Плагин опирается на несколько поверхностей интерфейса DSH, которые не входят в
стабильный публичный API: слоты `settings.section` и `settings.section.icon`,
блок `plugins.bundle.config`, кнопку `sidebar.footer.action` и атрибуты
`data-model-id` / `data-provider-id`, которые пишет селектор моделей. Панель
баланса слот `shell.overlay` не использует: она позиционируется внутри слота
сайдбара. В [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md) перечислены каждая
поверхность с последствием её исчезновения и клиентские модули, которые манифест
объявляет через `dsh.client.inject`.

## Ограничения

- Уровни вытаскиваются из установщика, а не из API. Если оба адреса установщика
  недоступны, текущие уровни сохраняются, а новые модели получают полный ряд по
  `supports_reasoning`; прогон сообщает `levelsSource: none`.
- Каталог CVC не фильтруется по ключу: `/v1/models` показывает всё, а
  доступность решается конкретным запросом (`403 This model is not enabled for
  the API key`). Скрыть модели, которые ключ не обслуживает, плагин не может.
- Схема DSH ограничивает **ключи** `reasoningEfforts`
  (`off/minimal/low/medium/high/xhigh/max`), а значения — произвольное проводное
  написание. Поэтому уровень `thinking` из установщика едет как
  `high: thinking`, и плагин повторяет это правило.
- Модель, у которой каталог не объявил модальности, сохраняет текущий `input`;
  явный `supports_vision: false` убирает `image`.
- Маршрут, настроенный через `modelOverrides`, отклоняется с понятной ошибкой:
  DSH не принимает `modelOverrides` рядом с `models`, такой маршрут нужно
  сначала перевести на явный список.
- Бейдж коэффициента рисуется в меню выбора модели у композера и на кнопке
  текущей модели. Команда `/model` рисует строки своим попапом без тех же
  атрибутов, поэтому там бейджа нет.
- Сопоставление бейджа сводит регистр, точки и подчёркивания в id модели к
  дефису: каталог CheapVibeCode и адаптер DSH могут писать одну модель
  по-разному. Если и после этого кандидатов больше одного, бейдж не ставится.
- Баланс показывается в единицах провайдера, ровно как их отдаёт `/v1/balance`;
  в деньги плагин их не пересчитывает.
- Автоматические прогоны пишут через тот же редактор, но только когда HMR-сервис
  хоста отдаёт пригодный контекст транзакции. На хосте, где это не так, таймер
  считает разницу и пишет предупреждение вместо записи; в этом случае запустите
  `cvc_catalog action=apply` или кнопку **Применить каталог**.
- Фоновой работы при выключенных функциях нет: когда все три выключены, плагин не
  создаёт таймеров и не делает ни одного запроса к провайдеру.

## Проверка и откат

```powershell
# план без записи
cvc_catalog action=plan
```

## Разработка

```powershell
npm install
npm test                    # node --test test/*.mjs
npm run build               # пересборка client.js из src/client/**
node tools/assert-pack.mjs  # проверка состава npm-тарбола
```

`index.js` и `lib/**` — обычный ESM, без сборки. Браузерная половина
собирается из `src/client/**` в `client.js`; собранный файл коммитится, поэтому
пакет работает и из npm, и из git без запуска сборки на машине пользователя. CI
пересобирает его и падает, если закоммиченный файл отличается от исходников; ещё
одна работа проверяет, что в тарбол попали обещанные пакетом файлы.

Сборка идёт через `tsdown`, в чьём собственном поле `engines` требуется Node
`^22.18` или `>=24.11`, поэтому в CI сборка выполняется на Node 22. Установка из
npm и работа плагина идут на Node 20 или новее: собранный `client.js` лежит в
пакете, а установка из npm скрипт сборки не запускает.

Локально подключённый бандл связан ссылкой на каталог, а не копией: правка
файлов сама новый код не поднимает — DSH подхватит модуль после реконсиляции
профиля (любое изменение патча) или перезапуска приложения.

## Безопасность

См. [SECURITY.md](SECURITY.md). Плагин обращается только к хостам провайдеров и
адресам установщиков из своей конфигурации, ключ разрешается на хосте по имени и
в браузер не попадает, а релизы npm несут provenance из GitHub Actions.

## Переехало из

Функции коэффициентов и баланса перенесены из двух прежних плагинов,
`cvc-model-coeff-plugin` и `cvc-balance-plugin`. Оба репозитория остаются
доступными как архивы; при установке этого плагина их нужно убрать из профиля —
точные шаги в [docs/UPGRADING.md](docs/UPGRADING.md).
